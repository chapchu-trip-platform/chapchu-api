# 032. 공용 코드값 조회는 인증 없이 연다

## 배경

`POST /pets`는 견종을 **ID로** 받는데, 클라이언트가 그 ID를 얻을 방법이 없었다.

견종 ID는 시딩 순서에 따라 DB가 만든다(`V7`에서 UUID → `INT GENERATED ALWAYS AS IDENTITY`로 바뀌었다).
환경마다 값이 달라질 수 있으므로 코드에 하드코딩하면 안 된다. 값이 나오는 유일한 곳은
`PetResponse.breedId`인데, 그걸 보려면 **이미 등록된 반려동물이 있어야** 한다. 등록하려면 `breedId`가 필요하다.

```
반려동물 등록  →  breedId 필요
     ↑                  ↓
     └──── 알 방법이 없음 ────┘
```

닭과 달걀이라 반려동물 등록 기능 전체를 쓸 수 없었다. `GET /preferences/options`가 같은 이유로 만들어졌다
(`docs/decisions/027` 주변 맥락 참고).

## 결정

`GET /breeds`를 추가하고, **인증을 걸지 않는다.**

```java
public static final String[] PUBLIC_GET_PATHS = {"/places", "/places/**", "/weather", "/breeds"};
```

### 왜 공개인가

신규 유저는 **온보딩 화면에서 반려동물을 등록한다.** 그 시점에 유저가 가진 것은 `registration_token`뿐이고
access token은 아직 없다. 인증을 걸면 온보딩에서 견종 목록을 못 불러와 등록 자체가 막힌다.

견종은 유저와 무관한 고정 코드값이라 공개해도 드러나는 정보가 없다.

### 남은 문제

**`GET /preferences/options`는 아직 인증이 걸려 있다.** 온보딩에서 선호 사항도 함께 받는다면 같은 이유로
막힌다. 통합 회원가입 API를 만들 때 같이 풀어야 한다.

## 견종 데이터

`V8__seed_breeds_full.sql`에서 157종을 심는다.

`V7`이 `breeds` 테이블을 DROP 후 재생성하면서 `V2`의 12종이 사라졌고 재시드가 없어 테이블이 비어 있었다.
견종이 하나도 없으면 반려동물 등록 자체가 불가능하므로 사라진 12종까지 전부 다시 심는다.

- 국제 견종은 FCI/AKC 기준으로 널리 쓰이는 품종을 추렸다. **캐글 데이터셋을 그대로 내려받은 것이 아니라
  손으로 정리한 목록이다.** 빠진 품종이 있으면 마이그레이션을 추가하면 된다.
- 사진은 넣지 않는다. 선택지에는 이름만 있으면 되고, 이미지는 별도 자산 관리가 필요하다.
- 순종이 아닌 경우를 위해 **`믹스견`**을 넣었다. 교배 조합이 무한하므로 개별 품종으로 나누지 않는다.
- `breed_name`에 UNIQUE를 걸어 앞으로 같은 이름이 중복 등록되지 않게 했다.

## 에이전트 행동 지침

- **UUID를 입력으로 받는 API를 만들면, 그 UUID를 얻을 조회 API가 있는지 먼저 확인하라.** 없으면 그 기능은
  존재하지 않는 것과 같다.
- 시드 데이터의 ID를 DB가 만들면 환경마다 값이 달라진다. 클라이언트가 참조해야 하는 코드값이라면
  조회 API가 반드시 함께 있어야 한다.
- **PK 타입을 바꾸는 마이그레이션은 엔티티도 같이 고쳐야 한다.** `ddl-auto: validate`라 어긋나면 기동 자체가
  실패한다. `V7`이 그렇게 배포되어 운영이 내려갔다.
- 온보딩 화면에서 쓰는 코드값 조회는 **인증을 걸지 마라.** 그 시점에는 access token이 없다.
