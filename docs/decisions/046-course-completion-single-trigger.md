# 046 — 코스 완료는 FE 명시 호출 하나로 통일

## 상태

- [x] 확정됨 (Accepted)

## 결정

코스 완료(`travel_courses.is_completed = true`)는 **`POST /courses/{courseId}/complete` 명시 호출**로만 이뤄진다.
나머지 두 자동완료 경로는 제거한다.

| 경로 | 이전 | 이후 |
|---|---|---|
| ① `CourseService.completeCourse` (FE 명시 호출) | 완료 | **유일한 완료 경로** |
| ② `CourseService.visitPlace` — 도착지 체크인 시 `course.complete()` | 완료 | **제거** |
| ③ `ReviewService` — 전 스탑 리뷰 시 `is_completed = true` UPDATE | 완료 | **제거** |

## 정책

**전부 방문해야 완료.** 전부 방문했는지는 FE가 판단해 "완료 여부만" 보내고, 백엔드는 방문 검증을 하지 않는다.
미방문 장소를 제외하고 완료하는 "부분 완료"는 없다. 끝까지 돌지 않은 코스는 완료가 아니라
삭제(`DELETE /courses/{courseId}`) 대상이다.

## 이유

완료 트리거가 세 갈래라 같은 코스가 서로 다른 시점에, 서로 다른 조건으로 완료됐다.

- ②는 **도착지 한 곳만 체크인해도** 코스를 완료시킨다. 중간 스탑을 건너뛰어도 완료가 되므로
  "전부 방문해야 완료" 정책과 정면으로 어긋난다.
- ③은 리뷰 작성이라는 **완료와 무관한 행위**가 완료를 만든다. 게다가 ②로 이미 완료된 코스에
  뒤늦게 리뷰를 쓰면 `is_completed = false` 조건 때문에 조용히 무시돼, 코드를 읽는 사람이
  언제 완료되는지 예측할 수 없었다.
- 완료 시점이 예측 불가능하면 "미완료 코스만 삭제"(decisions 참고: 코스 하드삭제) 같은
  후속 규칙도 세울 수 없다.

## 에이전트 행동 지침

- `is_completed`를 `true`로 바꾸는 코드를 `CourseService.completeCourse` 밖에 새로 만들지 마라.
- 체크인(`visitPlace`)은 방문 기록과 스탬프 발급까지만 한다. 완료를 건드리지 마라.
- 리뷰·사진·게시글 작성은 코스 완료 상태를 바꾸지 않는다.
- 백엔드에 "전부 방문했는지" 검증을 추가하지 마라. 그 판단은 FE 몫으로 확정됐다.
