== 개요

PetTrip 반려동물 동반 여행 플랫폼 REST API 명세입니다.

== 공통

=== 요청 헤더

[source,http]
----
Authorization: Bearer {access_token}
Content-Type: application/json
----

=== 응답 코드

|===
| 상태 코드 | 설명

| `200 OK` | 성공
| `201 Created` | 생성 성공
| `400 Bad Request` | 요청 파라미터 오류
| `401 Unauthorized` | 인증 필요
| `403 Forbidden` | 권한 없음
| `404 Not Found` | 리소스 없음
| `500 Internal Server Error` | 서버 오류
|===

=== 오류 응답 형식

모든 오류는 같은 형태로 내려간다.

[source,json]
----
{
  "code": "INVALID_REQUEST",
  "message": "photoId: 필수 값입니다."
}
----

어느 필드가 잘못됐는지 특정할 수 있으면 `fieldErrors`가 함께 내려간다. 여러 필드가 동시에
틀렸으면 전부 담긴다. `message`는 그중 첫 번째를 사람이 읽기 좋게 옮긴 요약이다.

[source,json]
----
{
  "code": "INVALID_REQUEST",
  "message": "petId: 필수 값입니다.",
  "fieldErrors": [
    { "field": "petId", "message": "필수 값입니다." },
    { "field": "photoId", "message": "필수 값입니다." },
    { "field": "courseId", "message": "UUID 형식이 아닙니다." }
  ]
}
----

`fieldErrors`가 붙는 경우는 셋이다.

* 요청 본문 검증 위반 (`@NotNull`, `@Size` 등)
* UUID·숫자·enum 역직렬화 실패 — 값 형식이 틀려 검증까지 가지 못한 경우
* 요청이 가리키는 자원이 없거나 본인 것이 아닌 경우

마지막 경우 "없음"과 "남의 것"을 구분하지 않는다. 구분하면 남의 자원 ID가 존재하는지
확인해 주는 셈이 되기 때문이다.

필드를 특정할 수 없는 오류(본문 자체가 깨진 JSON 등)에서는 `fieldErrors`가 생략된다.

== 인증 API (BFF)

chapchu-api가 OAuth2 Confidential Client로서 구글 로그인 흐름 전체를 대리 처리합니다.
FE는 `/auth/login` 만 알면 되고, 코드 교환·토큰 저장·갱신은 서버가 처리합니다.

=== 로그인 시작

`GET /auth/login`

FE가 *브라우저를* 이 URL로 이동시킵니다. 이후 흐름은 서버가 자동 처리합니다.

[.request]
==== 요청 파라미터 (선택)

|===
| 파라미터 | 필수 | 설명

| `redirect`
| 아니오
| 로그인 완료 후 리다이렉트할 FE 콜백 URL. 생략 시 서버 기본값(`FE_REDIRECT_URL`) 사용. 허용된 CORS origin 이외의 값은 무시됩니다.
|===

[source,js]
----
// 배포 환경 (파라미터 생략)
window.location.href = 'https://api.chapchu.site/auth/login';

// 로컬 개발
const redirect = encodeURIComponent(window.location.origin + '/auth/callback');
window.location.href = `https://api.chapchu.site/auth/login?redirect=${redirect}`;
----

[.response]
==== 응답

로그인 완료 후 `{redirect}` 경로로 리다이렉트합니다.

* *기존 유저*: `{redirect}#access_token={JWT}`
* *신규 유저*: `{redirect}?registration_token={token}`

NOTE: access_token은 URL fragment(`#`)로 전달됩니다. 서버 로그에 남지 않으며 FE 스크립트에서만 읽을 수 있습니다.

=== OAuth 콜백

`GET /auth/callback`

구글 로그인 완료 후 chapchu-auth가 인가 코드를 이 엔드포인트로 리다이렉트합니다.
서버가 코드를 토큰으로 교환하고, 결과에 따라 FE 콜백으로 다시 리다이렉트합니다.

* *기존 유저*: `code`·`state`를 검증하고 access_token을 발급해 `{redirect}#access_token={JWT}`로 리다이렉트합니다.
* *신규 유저*: `registration_token`을 담아 `{redirect}?registration_token={token}`로 리다이렉트합니다.

쿼리 파라미터: `code`, `state`(기존 유저 흐름), `registration_token`(신규 유저 흐름).
`code`가 비었거나 `state`가 쿠키와 불일치하면 `400 Bad Request`.

=== 통합 회원가입

`POST /auth/signup`

닉네임·선호 사항·반려동물을 **한 번에** 등록합니다.
성공 후 FE에서 다시 `/auth/login`으로 이동해 토큰을 발급받습니다.

이전에는 반려동물 두 마리를 등록하려면 다섯 번을 호출해야 했습니다.

[source]
----
POST /auth/register → (구글 재로그인) → POST /users/me/preferences → POST /pets → POST /pets
----

중간에 하나라도 실패하면 절반만 만들어진 계정이 남았습니다.
지금은 전부 한 트랜잭션이라 도중에 실패하면 아무것도 남지 않고, **같은 토큰으로 그대로 재시도**할 수 있습니다.

**인증이 필요 없습니다.** 이 시점에 사용자가 가진 것은 `registration_token`뿐입니다.
선택지를 받는 `GET /breeds`, `GET /activities`, `GET /preferences/options`도 같은 이유로 열려 있습니다.

==== 오류

|===
| 상태 코드 | `code` | 언제

| `400 Bad Request` | `INVALID_REQUEST` | 닉네임이 비었거나 30자 초과, 반려동물 필수값 누락
| `401 Unauthorized` | `UNAUTHORIZED` | 가입 토큰 형식 오류 · 서명 불일치 · 10분 만료
| `404 Not Found` | `NOT_FOUND` | 없는 견종·활동·지역·테마·이동수단 ID
| `409 Conflict` | `CONFLICT` | 이미 가입된 계정이거나 닉네임이 이미 사용 중
| `502 Bad Gateway` | `EXTERNAL_API_ERROR` | 인증 서버에 연결 실패. 잠시 후 재시도 안내
|===

=== access_token 갱신

`POST /auth/refresh`

refresh_token 쿠키가 자동으로 포함되므로 FE는 별도 헤더 없이 호출합니다.
반드시 `credentials: 'include'` (fetch) 또는 `withCredentials: true` (axios) 설정이 필요합니다.
요청은 `refresh_token` HttpOnly 쿠키만 필요하고 본문은 없습니다.

[.response]
==== 응답 (성공)

`200 OK` — 새 access_token을 발급합니다. (refresh_token 회전)

[.response]
==== 응답 (쿠키 없음)

refresh_token 쿠키가 없으면 `401 Unauthorized`를 반환합니다. FE는 `/auth/login`으로 이동시킵니다.

include::{snippets}/auth-refresh-no-cookie/http-request.adoc[]
include::{snippets}/auth-refresh-no-cookie/http-response.adoc[]

=== 프로필 사진 설정

`PATCH /users/me/photo`

=== 선호 사항 선택지 조회

`GET /preferences/options`

선호 사항 등록/수정은 지역·테마·이동수단을 **UUID로** 받습니다.
코드값은 DB 시딩 시 생성되므로 하드코딩할 수 없고, 이 API로 받아서 써야 합니다.

|===
| 항목 | 값

| `regions`
| 광역시·자치도 17개 (서울·부산·대구·인천·광주·대전·울산·세종·경기·강원·충북·충남·전북·전남·경북·경남·제주)

| `themes`
| TourAPI 대분류 8종 (관광지·문화시설·축제공연행사·여행코스·레포츠·숙박·쇼핑·음식점)

| `transportMethods`
| 자가용·대중교통·도보·자전거
|===

NOTE: 테마는 TourAPI의 `contentTypeId`와 1:1로 맞춰져 있습니다. 유저 선호와 장소 분류가 같은 축을 쓰기 위해서입니다.

**인증이 필요 없습니다.** 신규 유저는 회원가입 화면에서 선호 사항을 고르는데,
그 시점에는 아직 access token이 없기 때문입니다.

=== 스탬프 도감 조회

`GET /users/me/stamps`

시·도 단위로 스탬프가 하나씩 있다. 코스에 담긴 장소를 방문 인증하면 그 장소가 속한 시·도의
스탬프가 발급되고, 같은 지역을 다시 방문하면 `stampCount`만 올라간다.

**미획득 지역도 함께 내려간다.** `acquired`가 `false`인 항목을 회색으로 그리면 된다.

지역 판정은 TourAPI `areaCode`로 한다. 아직 동기화되지 않아 `places.area_code`가 비어 있는
장소는 스탬프가 발급되지 않는다. 이 경우에도 방문 인증 자체는 정상 처리된다.

NOTE: `imageUrl`(지자체 마스코트)은 이미지가 준비되는 대로 채운다. 그때까지는 `null`이다.

== 사진 API

사진은 S3 presigned URL 방식으로 다룹니다. 업로드는 `upload-url`로 발급받은 URL에 FE가 직접 PUT하고,
저장(`POST /photos`)으로 메타데이터를 기록합니다. 조회는 `GET /photos/{photoId}`로 다운로드용
presigned URL을 발급받습니다. 버킷은 비공개이며 서버가 소유권 검증 후 URL을 발급합니다.
`type`으로 사진 용도(PROFILE/POST/REVIEW)를 지정하면 S3 키가 `{소문자 type}/{userId}/...`(예: `review/...`)로 정리됩니다.

`upload-url`과 `POST /photos`는 모두 **배열**로 여러 장을 한 번에 처리합니다(리뷰·게시글에 사진 여러 장 첨부).
발급 응답의 `fileName`으로 어느 URL이 어느 원본 파일인지 매칭하고, 저장은 한 트랜잭션으로 처리됩니다.

=== 게시글 작성

`POST /posts`

`petId`, `courseId`, `photos`가 **모두 선택**이다. 본문만 보내도 글이 등록된다.

== 여행 API

=== 코스 생성

`POST /courses`

JWT 인증이 필요합니다. `petId`(본인 반려동물)가 필수이며, FE가 수집한 날씨 정보(temperature, humidity, weatherStatus)를 함께 전달합니다.
**중간 개수(`intermediateStopCount`)는 없어졌습니다.** 사용자가 대략 목적지 좌표로 `POST /recommended-places`(limit=5)를 호출해 반려견 장소 후보를 받은 뒤, 그중 하나를 골라 그 정보를 `destination` 객체로 통째로 담아 보냅니다. 서버는 이 도착지를 Place로 upsert해 **고정 도착 스탑**으로 두고, 출발~도착 사이 후보를 모아 **AI가 취향(선호 활동)·거리·날씨를 보고 중간 스탑을 최대 3개까지 큐레이션**합니다. (중간 개수 N은 거리·반려동물 체력·날씨로 산정 — docs/decisions/043)
따라서 응답 `places`는 **큐레이션 중간(0~3) + 고정 도착지 1** 로 구성되며(최대 4곳), 각 스탑에 `reason`(왜 이 곳)이 담깁니다. 후보가 없어도 도착지만으로 코스가 생성됩니다(404 아님).
응답에 각 장소의 위경도, 이미지, 반려동물 정책이 포함됩니다.

== 앨범 API

앨범은 별도 저장 없이 **내가 쓴 리뷰들의 사진을 모아 보여주는** 파생 조회입니다(리뷰 사진 = `review_photos`).

=== 내 앨범 조회

`GET /users/me/album`

JWT 인증이 필요합니다. 내 리뷰 사진을 **최신 리뷰 → 리뷰 내 사진 순서**로 펼쳐서 반환합니다.
각 항목에 `reviewId`·`placeId`가 있어 사진에서 원 리뷰·장소로 되짚을 수 있습니다.
`downloadUrl`은 presigned GET URL(10분)입니다.

== 추천 API

=== 장소 추천

`POST /recommended-places`

JWT 인증이 필요합니다. 기준 좌표를 기반으로 반려동물 동반 가능 장소를 추천합니다.
DB에 저장되지 않습니다. 코스 생성 전 미리보기, 단독 탐색, **코스 도착지 후보 선택**(도착지 좌표로 호출) 용도로 사용합니다.
반려동물 크기 하드 필터 → 리뷰 임베딩 RAG 랭킹 순서로 결과를 반환합니다.
RAG 쿼리에는 날씨·기온·반려동물 크기/나이뿐 아니라 **선호 활동(예: 수영)** 이 반영돼, 취향에 맞는 장소가 상위로 올라옵니다.
`limit`을 주면 상위 N개만 반환합니다(도착지 후보는 5). 없거나 0 이하면 제한 없음.
