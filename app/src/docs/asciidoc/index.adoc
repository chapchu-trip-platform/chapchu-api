== 개요

PetTrip 반려동물 동반 여행 플랫폼 REST API 명세입니다.

== 공통

=== 요청 헤더

[source,http]
----
Authorization: Bearer {access_token}
Content-Type: application/json
----

=== 응답 코드

|===
| 상태 코드 | 설명

| `200 OK` | 성공
| `201 Created` | 생성 성공
| `400 Bad Request` | 요청 파라미터 오류
| `401 Unauthorized` | 인증 필요
| `403 Forbidden` | 권한 없음
| `404 Not Found` | 리소스 없음
| `500 Internal Server Error` | 서버 오류
|===

== 인증 API (BFF)

chapchu-api가 OAuth2 Confidential Client로서 구글 로그인 흐름 전체를 대리 처리합니다.
FE는 `/auth/login` 만 알면 되고, 코드 교환·토큰 저장·갱신은 서버가 처리합니다.

=== 로그인 시작

`GET /auth/login`

FE가 *브라우저를* 이 URL로 이동시킵니다. 이후 흐름은 서버가 자동 처리합니다.

[.request]
==== 요청 파라미터 (선택)

|===
| 파라미터 | 필수 | 설명

| `redirect`
| 아니오
| 로그인 완료 후 리다이렉트할 FE 콜백 URL. 생략 시 서버 기본값(`FE_REDIRECT_URL`) 사용. 허용된 CORS origin 이외의 값은 무시됩니다.
|===

[source,js]
----
// 배포 환경 (파라미터 생략)
window.location.href = 'https://api.chapchu.site/auth/login';

// 로컬 개발
const redirect = encodeURIComponent(window.location.origin + '/auth/callback');
window.location.href = `https://api.chapchu.site/auth/login?redirect=${redirect}`;
----

[.response]
==== 응답

로그인 완료 후 `{redirect}` 경로로 리다이렉트합니다.

* *기존 유저*: `{redirect}#access_token={JWT}`
* *신규 유저*: `{redirect}?registration_token={token}`

NOTE: access_token은 URL fragment(`#`)로 전달됩니다. 서버 로그에 남지 않으며 FE 스크립트에서만 읽을 수 있습니다.

=== 신규 유저 등록

`POST /auth/register`

신규 유저 온보딩 시 닉네임을 등록합니다. 성공 후 FE에서 다시 `/auth/login`으로 이동해 토큰을 발급받습니다.

[.request]
==== 요청

[source,http]
----
POST /auth/register HTTP/1.1
Content-Type: application/json

{
  "registrationToken": "온보딩 콜백에서 받은 토큰",
  "nickname": "사용자 닉네임"
}
----

[.response]
==== 응답

* `200 OK` — 등록 성공
* `400 Bad Request` — 토큰 만료 또는 닉네임 중복

=== 통합 회원가입

`POST /auth/signup`

닉네임·선호 사항·반려동물을 **한 번에** 등록합니다.
성공 후 FE에서 다시 `/auth/login`으로 이동해 토큰을 발급받습니다.

이전에는 반려동물 두 마리를 등록하려면 다섯 번을 호출해야 했습니다.

[source]
----
POST /auth/register → (구글 재로그인) → POST /users/me/preferences → POST /pets → POST /pets
----

중간에 하나라도 실패하면 절반만 만들어진 계정이 남았습니다.
지금은 전부 한 트랜잭션이라 도중에 실패하면 아무것도 남지 않고, **같은 토큰으로 그대로 재시도**할 수 있습니다.

**인증이 필요 없습니다.** 이 시점에 사용자가 가진 것은 `registration_token`뿐입니다.
선택지를 받는 `GET /breeds`, `GET /activities`, `GET /preferences/options`도 같은 이유로 열려 있습니다.

==== 오류

|===
| 상태 코드 | `code` | 언제

| `400 Bad Request` | `INVALID_REQUEST` | 닉네임이 비었거나 30자 초과, 반려동물 필수값 누락
| `401 Unauthorized` | `UNAUTHORIZED` | 가입 토큰 형식 오류 · 서명 불일치 · 10분 만료
| `404 Not Found` | `NOT_FOUND` | 없는 견종·활동·지역·테마·이동수단 ID
| `409 Conflict` | `CONFLICT` | 이미 가입된 계정이거나 닉네임이 이미 사용 중
| `502 Bad Gateway` | `EXTERNAL_API_ERROR` | 인증 서버에 연결 실패. 잠시 후 재시도 안내
|===

NOTE: `POST /auth/register`는 닉네임만 등록하는 이전 방식입니다. 선호 사항과 반려동물까지 받으려면 이 API를 쓰세요.

=== access_token 갱신

`POST /auth/refresh`

refresh_token 쿠키가 자동으로 포함되므로 FE는 별도 헤더 없이 호출합니다.
반드시 `credentials: 'include'` (fetch) 또는 `withCredentials: true` (axios) 설정이 필요합니다.

[.request]
==== 요청

[source,http]
----
POST /auth/refresh HTTP/1.1
Cookie: refresh_token={token}
----

[.response]
==== 응답

[source,json]
----
{
  "access_token": "새로 발급된 JWT"
}
----

* `401 Unauthorized` — refresh_token 없음 또는 만료 → FE에서 `/auth/login`으로 이동

=== 로그아웃

=== 선호 사항 선택지 조회

`GET /preferences/options`

선호 사항 등록/수정은 지역·테마·이동수단을 **UUID로** 받습니다.
코드값은 DB 시딩 시 생성되므로 하드코딩할 수 없고, 이 API로 받아서 써야 합니다.

|===
| 항목 | 값

| `regions`
| 광역시·자치도 17개 (서울·부산·대구·인천·광주·대전·울산·세종·경기·강원·충북·충남·전북·전남·경북·경남·제주)

| `themes`
| TourAPI 대분류 8종 (관광지·문화시설·축제공연행사·여행코스·레포츠·숙박·쇼핑·음식점)

| `transportMethods`
| 자가용·대중교통·도보·자전거
|===

NOTE: 테마는 TourAPI의 `contentTypeId`와 1:1로 맞춰져 있습니다. 유저 선호와 장소 분류가 같은 축을 쓰기 위해서입니다.

**인증이 필요 없습니다.** 신규 유저는 회원가입 화면에서 선호 사항을 고르는데,
그 시점에는 아직 access token이 없기 때문입니다.

=== 선호 사항 수정

`PATCH /users/me/preferences`

최초 등록과 이후 수정을 나누지 않습니다. 선호 사항은 유저에 종속된 단일 값이라
따로 생성되는 리소스가 아니고, 서버가 두 경우를 구분하지 않습니다.

보내지 않은 항목은 **그대로 유지**됩니다. 세 항목을 모두 보내면 전부 설정되고,
`regionIds`만 보내면 테마·이동수단은 건드리지 않습니다.

WARNING: `POST /users/me/preferences`는 제거되었습니다. `PATCH`로 바꿔 주세요.
본문 형식과 응답은 같습니다.

NOTE: 회원가입 시점의 최초 등록은 `POST /auth/signup`이 함께 처리합니다.
